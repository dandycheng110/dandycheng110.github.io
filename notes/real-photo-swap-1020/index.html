怎麼判斷馬賽那條沒經過香港：東京之後的下一個看得到的節點是 Tata 美國網段，ping 最低 236 ms；如果它在香港，從台灣 ping 只會是 20 ms 上下。不過延遲只能證明這個節點本身不在香港，沒回應的那幾跳還是看不到，所以只能說「沒看到香港」。

指定連馬賽機房

--resolve 只是告訴 curl 要連哪個 IP，網址和 HTTPS 憑證都不變：

# 查清單（Commons API）
curl --resolve commons.wikimedia.org:443:185.15.58.224 \
  -G 'https://commons.wikimedia.org/w/api.php' \
  --data-urlencode 'action=query' --data-urlencode 'format=json' \
  --data-urlencode 'generator=search' --data-urlencode 'gsrnamespace=6' \
  --data-urlencode 'gsrsearch=hyrax hastemplate:QualityImage filetype:bitmap' \
  --data-urlencode 'prop=imageinfo' \
  --data-urlencode 'iiprop=url|size|extmetadata|commonmetadata'

# 下載圖檔
curl --resolve upload.wikimedia.org:443:185.15.58.240 \
  -o photo.jpg 'https://upload.wikimedia.org/wikipedia/commons/…'

06驗真：確認是相機實拍

舊圖會被換掉，就是因為它看起來像 AI 生成。所以新圖除了授權，還要確認是真的照片。

08安全上線

風險做法
本機 main 上還有其他還沒要上線的改動，一推就整包上去
從線上版另開 git worktree 修改，推送時寫明 git push origin <commit>:refs/heads/main
另一個 AI 工作階段同時在改同一個 repo
只 git add 自己改的檔案再 commit（不要用 -a 或 git add .）。換圖記得把圖檔一起列進去，例如 git add index.html assets/hyrax.jpg assets/hyrax-badge.jpg。別人沒 commit 的檔案一個都不碰，再傳訊息告訴對方
確認上線要連 github.io（Fastly，推定經香港）
改用 GitHub API 查 Pages 建置狀態和遠端檔案，不直接連網站
預覽時頁面會去抓 Google Fonts
預覽用的副本先拿掉外部字型；headless Chrome 加 --host-resolver-rules 擋掉所有外部網域
推完馬上看，可能還是舊圖
Pages 快取最久約 10 分鐘；強制重新整理：Chrome、Firefox 按 ⌘⇧R，Safari 按 ⌥⌘R
 
# 確認 Pages 用的是剛推的 commit，而且建置完成
gh api repos/<帳號>/<repo>/pages/builds/latest --jq '.status + " " + .commit'
# → built e48f77b…

推送那行 git push origin <commit>:refs/heads/main：冒號左邊是「要推哪一筆」，右邊是「推到哪個分支」（Git 叫它 refspec）。寫明白就不會把本機其他改動一起推上去。

10踩坑與解法

坑解法
首頁大圖的版位其實是圓形，第一版照直式裁
先讀 CSS 的 border-radius、object-fit，再決定裁法
Commons 回傳的縮圖網址換成 thumb.wikimedia.org
只取路徑，改從 upload.wikimedia.org 下載，一樣指定馬賽機房
zsh 寫 while read id path，結果 $PATH 被蓋掉，找不到 curl
path 是 zsh 的特殊變數，改名成 tp
連線檢查工具把 User-Agent 裡的網址當成要連的地方
User-Agent 不放網址
Commons API 連續查太快，回 429
每次請求間隔 0.3 秒，被擋的那一筆略過
ImageMagick 拼對照圖時找不到 Helvetica，號碼沒印出來
改用 Python Pillow 的內建字型畫號碼
改 repo 改到一半，發現另一個工作階段也在改
見第 08 節：只 commit 自己的檔案，推送寫明「哪一筆推到哪個分支」，並通知對方
