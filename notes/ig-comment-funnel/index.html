自動化漏斗 拆解手冊

你在 IG 短影片下留特定關鍵字、就被自動私訊、還被偵測有沒有追蹤、追蹤後才給 PPT / 指令集 / 網址、點進去還要填 email 問卷——這整套是怎麼運作的。逐層拆給你看。

核心技術 Meta Graph API · Private Replies 合法性 官方功能,非破解 代表工具 ManyChat / InstantDM 視角 逆向 + 合規雙軌

▍一句話總結

這不是外掛、不是爬蟲、更不是駭客技術。它就是 Meta 官方開放的「留言私訊回覆 (Private Reply) API」,搭一層「是否追蹤」的條件判斷,再接一條「落地頁 + 問卷」的個資收集漏斗。整套合法、公開、有官方文件,任何人申請一個 IG 商業帳號就能做。

§ 01 / FOUNDATION

先破除誤會:這是「官方功能」不是「破解」

很多人第一直覺是「這一定是私接 API 偷打的」或「用機器人在背後爬」。錯。這是 Meta 自己端出來、寫進開發者文件、還鼓勵大家用的功能,叫做 Instagram Private Replies。

運作核心很單純:當有人在你的貼文或 Reel 留言,Meta 會發一個 webhook 回呼,內容包含這則留言的 comment_id 與留言文字。系統收到後,可以針對這則留言「私下回覆一則訊息」——也就是直接私訊那位留言者。這就是整套魔法的起點。

ManyChat、InstantDM 這些你看到的工具,全都是 官方認證的 Meta Business Partner,整套建在合法的 Graph API 之上。它們做的事不是繞過 Meta,而是幫你把 Meta 開好的接口包成「不用寫程式的拖拉介面」。

關鍵限制(記住它,後面會反覆出現):你不能主動冷私訊 (cold DM) 任何沒先跟你互動過的人。對方必須先留言、限動回覆、或主動私訊,你才有資格回他。這是 Instagram API 的硬規則,對所有工具一視同仁。所謂「自動私訊」,本質是「自動回覆」,不是「自動發送」。
§ 02 / DATA FLOW

完整資料流:從一則留言到你的個資

把你經歷的整個過程畫成訊號路徑,長這樣。每一個方塊都是一個真實存在的技術環節:

◍ End-to-End Signal Path ◍
Stage 0 · Bait Reel / 貼文 + 行動呼籲 「想要這份資源?在下面留言『指令集』」
使用者留言關鍵字▼

✓ 有追蹤
直接私訊送資源 含連結 / 按鈕 / 檔案
✗ 沒追蹤

看出設計巧思了嗎?「資源」從來不是重點,你的 Email 才是。免費的 PPT、指令集只是「誘餌 (lead magnet)」,真正的目標是把你從「IG 上一個匿名留言」轉換成「名單裡一筆可重複行銷的聯絡人」。業界把這叫 lead generation funnel。

§ 03 / LAYER-BY-LAYER

逐層拆解:每一段的技術細節

① 觸發層 — Webhook 怎麼知道你留言了

你的帳號(必須是商業/創作者帳號)向 Meta 訂閱了 comments 這個 webhook 事件。任何人一留言,Meta 伺服器就主動 POST 一包 JSON 到自動化引擎事先登記好的網址。引擎拿到後做關鍵字比對,命中就往下走。重點是:這是 Meta「推」給你的,不是工具去「抓」的——所以即時、也不違規。

Meta → 你的 webhook 端點POST · comment_event
{
  "object": "instagram",
  "entry": [{
    "id": "<你的IG商業帳號ID>",
    "changes": [{
      "field": "comments",
      "value": {
        "id": "17890012345",        // 這則留言的 comment_id
        "text": "指令集",            // 留言內容 → 拿來比對關鍵字
        "from": { "id": "<留言者ID>", "username": "some_user" }
      }
    }]
  }]
}

② 回應層 — 一次的「私訊回覆」機會 + 24 小時窗

命中後,引擎拿著 comment_id 呼叫 Private Reply API,系統就用你的帳號私訊對方。注意兩個限制:

  • 一則留言只能私訊回覆「一次」。所以第一則訊息通常會放一個按鈕或請你回個字,目的是把對話「開啟」。
  • 對方一旦回覆(哪怕只回一個 emoji),就開啟 24 小時訊息窗。在這 24 小時內,你才能自由地連續發訊息、發按鈕、發檔案。這就是為什麼很多自動私訊會先問你「想要的話回 1」——它在合法地撐開那扇窗。
自動化引擎 → Meta(私訊回覆 + 按鈕模板)POST · send_message
{
  "recipient": { "comment_id": "17890012345" },   // 用留言ID當收件人
  "message": {
    "attachment": {
      "type": "template",
      "payload": {
        "template_type": "button",
        "text": "嗨!資源準備好了,點下面領取 👇",
        "buttons": [
          { "type": "web_url", "title": "領取指令集", "url": "https://落地頁..." }
        ]
      }
    }
  }
}

③ 偵測追蹤層 — 真相比你想的微妙(重點段)

這是大家最好奇的:「它怎麼知道我有沒有追蹤?」答案分兩種,而且市面上一半的人是「假的」:

A · 真檢查

工具確實有個系統欄位(ManyChat 叫 Follows your Instagram account / API 層的 is_user_follow_business),能讀出對方「當下是否追蹤你」。流程裡放個條件節點:有追蹤 → 給資源;沒追蹤 → 叫你先追蹤。

⚠ 但這欄位歷史上很不穩,只在用「新版 Unified 連接方式」綁定的帳號上才較可靠,常常抓不到或回空值。

B · 假檢查(更常見)

很多大帳號根本沒在檢查。他們只是私訊一句「記得先追蹤我喔」「確認你追蹤了嗎?」——然後不管你有沒有追蹤,照樣把資源丟給你。

它賭的是「社會順從心理」:多數人看到指示就乖乖按了追蹤。轉換率照樣漂亮,還省掉那個會出包的條件節點。

所以下次你看到「追蹤後才給」,有一半機率它其實沒在驗證,只是話術。這對你(資安背景)是個有趣的觀察:這是純粹的心理層 gating,不是技術層 gating。

④ 資源遞送層 — 為什麼老把你導去填 Email

理論上資源連結可以直接私訊給你,但老手都改用「先收 Email、再用 Email 寄資源」。原因:IG 訊息窗 24 小時就關了,但 Email 是永久的、可重複行銷的資產。業界數據很驚人——頂尖創作者用這招,Email 收集率可達 70%–85%。你拿到一份 PPT,他拿到一個可以一直寄你電子報的長期管道。這筆交易誰賺?

⑤ 個資/問卷層 — 漏斗的真正終點

落地頁那份「問卷」就是 capture form,常見用 Typeform、自架網頁、或工具內建表單。它向你要 Email(必填)、姓名、有時還有產業/需求(這是在做名單分眾 segmentation,方便日後精準推銷)。送出後你進 CRM,自動觸發「歡迎序列」——接下來幾天的行銷信,都是這一刻種下的。

§ 04 / BUILD PATHS

三種實作路徑:從零代碼到全自建

同一套效果,有三種做法。以你的技術背景(OSCP、跑 n8n、有 homelab),路徑 B、C 對你才有意思。

路徑怎麼做難度適合誰
A
零代碼		 直接用 ManyChat / InstantDM / Chatfuel。拖拉介面設關鍵字、條件、流程。月費約 US$14 起。Meta 官方夥伴,免碰 API。 低 純行銷者、想當天上線的人
B
半自建		 ManyChat 負責收訊息/守規,但在流程中插「External Request」節點,打到你自架的 webhook / n8n workflow。判斷邏輯、發資源、寫資料庫都自己控。 中 ← 你。已有 n8n + Mac mini homelab,可把名單接進自己的自動化
C
全自建		 自己申請 Meta App、過 App Review、自架 webhook server 訂閱 comments、直接呼叫 Graph API 的 /messages 與 Private Reply。完全掌控,但要處理 token、權限審核、24h 窗邏輯。 高 想徹底理解或做產品的人;練手好題目
§ 05 / MVP SETUP

想自己動手:最小可行架構

如果你要走路徑 C 親手搭一個,前置需求清單:

  1. 一個 Instagram 商業/創作者帳號,且必須連結到一個 Facebook 粉專。Meta API 兩者缺一不可——個人帳號完全不行。
  2. 一個 Meta Developer App,加入 Instagram Messaging 產品,申請 instagram_manage_messages、instagram_manage_comments 等權限(要過 App Review)。
  3. 一個對外的 webhook 端點(HTTPS)。你 homelab 用 Tailscale Funnel 或 Cloudflare Tunnel 暴露一個 n8n / 自寫服務即可。
  4. 訂閱 comments 與 messages webhook 欄位,通過 Meta 的驗證 challenge。

養號提醒

新帳號常常 webhook 不觸發、follower 欄位抓不到。實務上帳號要「活幾天、權限全開」之後才穩定。這不是 bug,是 Meta 的防濫用機制。

§ 06 / HARD RULES

鐵律與限制(踩了就是封號)

不能主動冷私訊

沒先互動過的人,你發不了第一則訊息。所有「自動私訊」本質都是「自動回覆既有互動」。違反 = 帳號被限制。

24 小時訊息窗

對方最後一次互動起算 24 小時內才能自由發訊。超過要用「付費的人工客服標籤」等特殊類別,且用途受限。

一留言只回一次私訊

Private Reply 對單一留言只有一次機會,後續對話得靠對方回訊撐開訊息窗。

帳號類型 + 速率限制

必須商業/創作者 + 連 FB 粉專。API 呼叫有速率上限,大量觸發要排隊,別想一秒灌爆。

§ 07 / COMPLIANCE

合規與法律(收個資這段最容易出事)

技術合法 ≠ 你怎麼用都合法。一旦進到「收 Email、寄行銷信」,你就踩進個資與行銷法規的地盤。對你尤其重要,因為你之後若拿這套經營「龍蝦 AI」名單,這些是你的責任:

機器人揭露 (Bot Disclosure)

多數地區(尤其 FTC 規範下)要求自動訊息不得偽裝成真人到有欺騙性的程度。別假裝「這是我本人秒回」到會誤導人的地步。

Email 行銷 — 台灣個資法 / CAN-SPAM / GDPR

台灣《個資法》:蒐集個資要告知目的並取得同意,且只能用於告知的目的。寄行銷信要附退訂機制(CAN-SPAM 也是)。若名單含歐盟用戶,GDPR 要求明確 opt-in 同意,罰則極重。「填表單換 PPT」必須讓人清楚知道你會用 Email 做什麼。

個資保管責任

你以資安人最懂:一旦你存了一張 Email 名單,你就是資料控管者,要負保護義務。外洩有通報與責任問題。別把名單隨便丟在沒加密的試算表或公開的 webhook log 裡。

別用「假追蹤檢查」做欺騙性 gating

§03 提到有人謊稱「驗證追蹤」其實沒驗。輕則話術、重則在某些情境構成欺騙性行銷。要嘛真的檢查,要嘛別把它講成技術保證。

§ 08 / RESEARCHER'S NOTE

給你的觀察 — 資安視角

跳出「怎麼做」,從你做 UAV/RF 安全與經營資安頻道的角度,這套漏斗其實是一個很好的「社交工程 + 資料收集」教材:

  • 誘餌經濟學:免費資源的成本趨近於零,換到的是高價值、可重複觸及的個資。這是不對稱交易——很適合做一支揭露影片。
  • 心理 gating > 技術 gating:「追蹤才給」很多時候是純話術。提醒觀眾:你看到的「限制」未必有技術在背後撐。
  • 合法工具的灰色用法:技術本身是 Meta 認證的,出問題的永遠是「資料怎麼用、有沒有告知」。這正是隱私議題的核心張力,跟你關心的東西同源。
  • OSINT 反向應用:你過去做過被動 OSINT 報告——這類漏斗的落地頁、表單、追蹤碼,本身就是可以被動分析的對象,能看出對方在收哪些欄位、串了哪些追蹤工具。
一句話收尾:技術門檻其實很低,真正的學問在「漏斗設計」與「合規邊界」。 想自己玩,從路徑 B 用你現有的 n8n 接一個最小版本開始,最快也最能學到東西。
