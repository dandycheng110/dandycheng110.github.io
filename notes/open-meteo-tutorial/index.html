01 拆解第一個請求

一條網址 = 端點 + 你要的東西

所有預報都打同一個端點 https://api.open-meteo.com/v1/forecast,後面用 query 參數告訴它:哪裡、要哪些天氣變數、什麼設定。三件事,三種顏色:

https://api.open-meteo.com/v1/forecast
?latitude=24.80&longitude=120.97
&current=temperature_2m,weather_code
&hourly=temperature_2m,precipitation_probability
&timezone=auto
端點 — 永遠不變 位置 — 經緯度(必填) 變數 — 你想要的天氣 設定 — 時區、單位…

唯二的必填參數是 latitude 與 longitude(WGS84 十進位度數)。其餘全部選填——你沒填的東西它就不算、也不回傳,所以請求越精簡、回應越快。

南北美洲提醒: 經度在格林威治以西要用負值。例如愛達荷州 Boise 是 latitude=43.62&longitude=-116.21。台灣在東經,維持正值即可。

03 三種時間維度

    
current、hourly、daily

    
同一個請求裡,你可以同時要這三種粒度的資料,各自獨立。理解它們的差別,就理解了 80% 的這支 API。


    
current — 此刻一個值

    
每個變數回傳單一數字,外加一個 time 與 interval(累計型變數如降水的回看秒數)。底層用 15 分鐘模型資料,適合做「現在幾度」的儀表板。


    
hourly — 逐小時陣列

    
回傳兩條平行陣列:hourly.time[] 與每個變數的數值陣列,索引一一對應。預設從今天 00:00 起算 168 小時(7 天)。畫折線圖、排程通知就靠它。


    
daily — 每日彙整

    
把逐時資料做 24 小時彙整(最高/最低/總和等)。注意:只要用了 daily,就必須同時帶 timezone,否則「一天」的邊界會錯亂。


    
回應裡每組資料都附一個對應的 _units 物件(例如 hourly_units.temperature_2m: "°C"),直接拿來當圖表標籤,不用自己猜單位。


    
幾個最常用的變數名

    

      

        
變數維度說明

        
          
temperature_2mcurrent / hourly地面 2 公尺氣溫

          
apparent_temperaturecurrent / hourly體感溫度(含風寒、濕度、輻射)

          
precipitation_probabilityhourly降水機率 %(集合模型推估)

          
weather_code三者皆可WMO 天氣代碼(見下一節)

          
wind_speed_10mcurrent / hourly10 公尺風速

          
temperature_2m_max / _mindaily當日最高 / 最低溫

          
sunrise / sunsetdaily日出 / 日落時間

        
      

    

  







  

    
04 解讀天氣

    
WMO 天氣代碼對照

    
weather_code 回傳的是一個數字,遵循世界氣象組織(WMO)的標準。你要自己把它對應成文字或圖示——測試器裡的小圖示就是這樣來的。

    

      

        
代碼意義

        
          
0☀️晴朗無雲

          
1 / 2 / 3⛅大致晴朗 / 局部多雲 / 陰

          
45 / 48🌫️霧 / 凍霧

          
51 / 53 / 55🌦️毛毛雨:小 / 中 / 大

          
61 / 63 / 65🌧️雨:小 / 中 / 大

          
66 / 67🌧️凍雨:小 / 大

          
71 / 73 / 75🌨️降雪:小 / 中 / 大

          
80 / 81 / 82🌧️陣雨:小 / 中 / 猛烈

          
85 / 86❄️陣雪:小 / 大

          
95⛈️雷雨(輕度至中度)

          
96 / 99⛈️雷雨夾冰雹

        
      

    

    
(*)夾冰雹的雷雨預報目前僅中歐地區提供。

  







  

    
05 接進你的程式

    
JavaScript · Python · n8n

    
沒有金鑰、沒有 OAuth,就是一個 fetch。下面三種,挑你的環境抄走即可。


    

      
      
      
    

    

      
// 瀏覽器或 Node 18+ 都能直接跑,免任何套件
const url = "https://api.open-meteo.com/v1/forecast"
  + "?latitude=24.80&longitude=120.97"
  + "&current=temperature_2m,weather_code"
  + "&hourly=temperature_2m&timezone=auto";

const res  = await fetch(url);
const data = await res.json();

console.log(data.current.temperature_2m, "°C");
console.log(data.hourly.temperature_2m.slice(0, 24)); // 未來 24 小時


      
# pip install requests
import requests

url = "https://api.open-meteo.com/v1/forecast"
params = {
    "latitude":  24.80,
    "longitude": 120.97,
    "current":   "temperature_2m,weather_code",
    "hourly":    "temperature_2m",
    "timezone":  "auto",
}

data = requests.get(url, params=params).json()
print(data["current"]["temperature_2m"], "°C")
print(data["hourly"]["temperature_2m"][:24])

06 再多一點控制

    
進階參數速查

    
這些都是選填,但很常用。記得規則:未來不會新增任何必填參數,所以你今天寫的網址,以後都不會壞。

    

      

        
參數預設作用

        
          
forecast_days7預報天數,最多 16 天

          
past_days0往回補昨天/前幾天(最多 92 天)

          
timezoneGMT設 auto 依座標自動判定當地時間;用 daily 時必填

          
temperature_unitcelsius改 fahrenheit

          
wind_speed_unitkmh可選 ms / mph / kn

          
start_date / end_date—指定日期區間(YYYY-MM-DD)

          
modelsauto手動指定氣象模型,預設「最佳匹配」自動組合

        
      

    


    
一次查多個地點

    
latitude 與 longitude 都能用逗號串多組座標:latitude=24.80,25.03&longitude=120.97,121.57。此時 JSON 會變成一個陣列,每個元素一個地點。


    
錯誤長什麼樣

    
參數打錯時,會回 HTTP 400 加一個 JSON:{ "error": true, "reason": "..." }。寫程式時先檢查 error 欄位,reason 會直接告訴你哪個變數拼錯了。


    
使用守則: 個人與非商業用途完全免費。商業或高流量需付費,並改用 customer- 前綴的端點加上 apikey。無論如何,加上快取、避免過度頻繁呼叫,是當個好公民的基本盤。
