SAUVC 模擬遠端操作 SOP

2026-10-19 · 給要從 Mac 操作新竹桌機模擬環境的隊友

從 Mac 打一行指令就能在新竹桌機啟動模擬，用瀏覽器開兩個網址操作，用完再一行關掉。所有程式都跑在桌機的容器裡，SSH 斷線不影響模擬，log 會自動留存。

連線架構第一次準備開啟使用關閉維護與排錯不能做的事

連線架構

Mac 用 SSH 叫桌機啟動或關閉模擬，再用 SSH 通道把桌機的 6080、80、8080 轉到 Mac 的 16080、18080、18081。

第一次使用前的準備

準備只要做一次。同學自己產生金鑰，再由機器主人把桌機開放給同學。

步驟誰做做什麼
1同學在 Mac 裝 Tailscale 並登入。
2同學產生專用金鑰：ssh-keygen -t ed25519 -f ~/.ssh/id_ed25519_sauvc，把 ~/.ssh/id_ed25519_sauvc.pub 的內容傳給機器主人。只傳 .pub，另一個檔案絕對不給。
3機器主人在 Tailscale 後台把桌機分享給同學的帳號。
4機器主人把同學的公鑰加進桌機的 C:\ProgramData\ssh\administrators_authorized_keys，一行一把。
5同學在 Mac 的 ~/.ssh/config 加入下面的設定，然後執行 ssh sauvc-win 測試。看到 PowerShell 提示字元就是成功。
 
Host sauvc-win
    HostName <桌機的 Tailscale 名稱，問機器主人>
    User <桌機的 Windows 帳號，問機器主人>
    IdentityFile ~/.ssh/id_ed25519_sauvc
    IdentitiesOnly yes
  • 第 4 步給的是系統管理員等級的權限，同學能操作整台桌機。所以只開放給信任的人；不用了就把那一行刪掉。
  • 如果 ssh sauvc-win 要求輸入密碼，代表金鑰沒對上。不要猜密碼，桌機是微軟帳號，連錯幾次就可能被鎖住。這時請找機器主人檢查第 4、5 步。

開啟

在 Mac 開兩個終端機視窗：一個用來啟動模擬，另一個開通道並一直保持開著。

步驟 1啟動模擬（在第一個視窗執行，大約要 30 秒）

ssh sauvc-win .\sauvc-sim.cmd start

最後會印出狀態表。每一行都正常的樣子是：Gazebo server、Gazebo 視窗、感測器 bridge、Web GUI 節點各 1 個，三個埠都有回應。

步驟 2開通道（在第二個視窗執行）

ssh -N -L 16080:localhost:6080 -L 18080:localhost:80 -L 18081:localhost:8080 sauvc-win

這個指令執行後不會有任何輸出，這是正常的。使用期間不要關掉這個視窗。

步驟 3用瀏覽器打開

畫面網址
Gazebo 畫面http://localhost:16080/vnc.html?autoconnect=true&resize=scale
Web GUIhttp://localhost:18080/?camera_port=18081

Mac 上只會用到 16080、18080、18081 三個埠，不影響你自己的 80、8080 網頁開發。如果模擬本來就在跑，第 1 步可以跳過，直接開通道就好。

使用

Gazebo 畫面是用來看的，控制潛航器要在 Web GUI 操作。模擬一啟動就在跑，不用按播放。

Gazebo 畫面

動作滑鼠操作
平移視角左鍵拖曳
旋轉視角中鍵拖曳，或 Shift + 左鍵拖曳
縮放滾輪，或右鍵拖曳
放大視窗雙擊 Gazebo 視窗的標題列
找潛航器右邊 Entity Tree 的 orca_auv 按右鍵 → Move to

畫面全黑或沒有反應時，先重新整理網頁。還是不行就看「維護與排錯」。

Web GUI

  • http://localhost:18080/?camera_port=18081 是儀表板，可以看深度、模式和相機畫面。
  • http://localhost:18080/controller?camera_port=18081 是手動操控頁。
  • 頁面上的連線燈是綠的就代表連上了。如果顯示 Link down，就檢查通道視窗是不是還開著。
  • 網址裡的 ?camera_port=18081 一定要加。沒加的話，相機會去連 Mac 自己的 8080，結果顯示 No stream。

自主任務（YOLO 辨識和行為樹）還不能跑。它用的是隊上的私有 image，要機器主人先登入 ghcr.io 才能下載。

關閉

用完請關掉模擬。Gazebo 會一直佔用桌機的顯示卡。

  1. 在通道視窗按 Ctrl-C。
  2. 停掉模擬：
ssh sauvc-win .\sauvc-sim.cmd stop

stop 會先把這次的 log 存到桌機的 ~/logs/sauvc/<日期-時間>/，再停掉所有程式。容器會保留，所以下次 start 比較快。如果要連容器一起關掉，改用 down。

維護與排錯

下面所有指令都從 Mac 執行，格式是 ssh sauvc-win .\sauvc-sim.cmd <指令>。要看持續輸出的 log 時，ssh 要加 -t。

指令用途
status看各元件有沒有在跑，有問題先跑這個
logs sim即時看 Gazebo 與 bridge 的 log（ssh -t，Ctrl-C 離開）
logs control即時看 Web GUI、控制器的 log
logs gui即時看 Gazebo 視窗的 log
logs vnc即時看 noVNC 的 log
restartstop 再 start，大部分問題重啟就好
build sim
build control		改了程式後重新編譯，編完要 restart
save-logs不停程式，只把目前的 log 存一份
down關掉模擬，連 orca-sim、orca-control 兩個容器一起關

存下來的 log 放在桌機 WSL 的 ~/logs/sauvc/。從 Mac 要這樣看：

ssh sauvc-win wsl -d Ubuntu-22.04 --cd ~ -- ls logs/sauvc
ssh sauvc-win wsl -d Ubuntu-22.04 --cd ~ -- tail -n 50 logs/sauvc/<資料夾>/sim.log

症狀原因處理

正常的感測器頻率：IMU 與深度計 100 Hz、前方相機約 12.6 Hz、下方相機約 15 Hz、深度影像約 30 Hz。

不能做的事

這台桌機同時是機器主人的碩論環境，下面幾件事不能做。

  • 不要動其他容器。名稱含 damn-vulnerable-drone、-lite 的容器是碩論實驗，不要停、不要刪。sauvc-sim 只會動 orca-sim 和 orca-control。
  • 不要自己下載或安裝東西，包括 apt、pip、docker pull、git clone。需要的話先問機器主人。
  • 不要 push 到隊上的 repo（NCTU-AUV）。程式改動要推到自己的 fork，再發 PR。
  • 不要把 80、8080、6080 開放給區網，也不要改 WSL 的網路模式。只用 SSH 通道看。
  • 不要猜 Windows 密碼。那是微軟帳號，連錯幾次就可能被鎖住。
